# 実装例

枠組みの部品を使って試験側で書くものの見本を置く。**ここにあるものは実行しない。** 読んで、自分の試験に合わせて書き換えるための雛形である。

[templates/](../templates/README.md) が空の CSV・JSON の雛形を持つのに対し、こちらは「部品をどう並べるか」の例を持つ。

## ここに置くもの

疾患・試験ごとに中身が変わるが、書き方は共通しているもの。

- 背景表の行項目の並び（[background-table.sas](background-table.sas)）

## 表示型の判定

試験Aの14の表示型（宣言で使われているのは13）について、汎用の部品として枠組みに置けるか、試験側へ出すかを判定した（2026-08-29）。判定はコメントを除いた実装だけを見て、その試験・疾患にしかない語（ADaM の派生変数名、検査項目のコード、部分集合の名前、表番号）への依存があるかで決めた。SAS と R の両方の実装を同じ基準で見て、判定は両系統で一致した。

汎用。表示の作法だけで閉じており、固有の語を1つも含まない。9件。

- `tab_prop`・`tab_prop_grp`・`tab_prop_grp_multi`・`tab_bg`・`tab_km`・`tab_cif`・`tab_count`・`tab_crs`・`fig_km`

ほぼ汎用だが、直書きが残る。2件。

- `tab_aegr` — グレードの区切り（Grade 1-2・3・4・5）が両系統に直書き。有害事象のグレードを使う領域では共通だが、区切り方は表示の選択なので、宣言の `levels=` で受ける形にすれば完全に汎用になる
- `tab_prop_tp` — 評価時点の並びと見出しは汎用の CSV（[../templates/](../templates/README.md) の `timepoint-map.csv` と同じ列）から読むので汎用。ただし部分集合の名前（同日検体を除く区分）が両系統に直書きされており、宣言の列で受ければ外せる

型は汎用だが、中身が試験固有。2件。

- `tab_list` — 列と見出しは宣言（`vars=`・`labels=`）で受けるので表示型は汎用。ただし一覧の元データを作る前処理を表番号で引き当てている（SAS は `%if &lblid = …`、R は `switch(r$lblid, …)`）。前処理は試験側に置き、表示型は引き当ての口だけを持つ形にする
- `tab_ref` — 自試験の値と文献値を列に並べる作りは汎用。行の定義（どの解析からどう引くか）と文献値は CSV 2つが持ち、その中身は試験固有。この2つのテンプレートは枠組みにまだ無い

試験固有。1件。

- `tab_mrlist` — 分子遺伝学的効果の症例別一覧。サブタイプごとに見る測定項目、判定の略号、3つの ADaM をまたぐ組み立てが疾患の知識そのものである。サブタイプと測定項目の対応は `subtypemap` で宣言へ出したが、残りは出せない

判定の副産物として、評価時点の CSV の名前が枠組みのテンプレート（`timepoint-map.csv`）と実装が読む先（試験側は疾患を冠した名前）で食い違っていることが分かった。列は同じである。テンプレートの名前が汎用側の正しい名前で、実装が疾患固有の名前を直接読んでいる。

## ここに置かないもの

- 実データ、被験者単位の情報、実試験の識別子
- 汎用の部品そのもの。それは [pipeline/scripts/](../pipeline/scripts/) が持つ
- 試験を1本通した記録。それは [trials/](../trials/README.md) が持つ

## 匿名化

例に出てくる変数名・水準名は、実際の試験から取ったものではなく、書き方を示すために作ったものである。実試験の実装を見本にするときは、疾患固有の変数名をその領域で一般的な名前へ置き換えてから置く。

## なぜ分けるか

汎用の部品と試験ごとの並びを同じファイルに置くと、次の試験で枠組みを使う人が、どこを書き換えてよいのか分からない。部品は触らずに使い、並びは自分の試験のものを書く、という境界を物理的に分ける。

境界が曖昧なまま置いていた時期があり、独立レビューで「汎用層に試験固有実装が混入している」と指摘された（2026-08-22）。
