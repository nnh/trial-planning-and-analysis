## 概要

2試験目（JALSG-CBF-AML220）を枠組みの形へ移す作業の中で、枠組み側の欠陥が3件出た。いずれも「雛形どおりに作った試験で検査が正しく働かない」という同じ型である。試験側で辻褄を合わせず、枠組みを直した。

最も重いのは3件目で、宣言を1行も書いていない状態で区間1の出口検査が「指摘はありません」を返していた。手順どおりに雛形を配置した直後にこれを回すと、区間1を終えたと読める。

## 決定事項

- `templates/timepoint-map.csv` に `subset` を足す。判断ではなく欠落である。`check-identifier-length.py` がこの列からデータサブセットの識別子を集めるのに、雛形が列を持っていなかった。雛形が実装より狭いまま配られると、雛形どおりに作った試験が必ず落ちる
- 残る4列（`denom`・`ecphase`・`adslvar`・`note`）は保留する。2試験目が独自に持つ4列（`visitnum`・`sheet_label_ja`・`epoch`・`spec_planned`）と重なるのは無く、共通するのは `note` だけである。昇格の判定は3試験目で行う
- 検査の終了コードの3値を、材料が無い場合にも適用する。`check-decisions.py` は台帳が無いとき例外で落ちていた。台帳を起こしていないのは区間1の途中では正しい状態なので、規則違反（1）ではなく検査が走らなかった（2）で返す
- 必須の宣言が空であることを区間1の出口条件の不足として扱う（`audit_declarations.py` の D08）。ファイルが在ることと宣言がそろっていることは別である。`variable-map.csv` だけは層を作りながら埋まるので warning にした

## 実測

- `templates/timepoint-map.csv` は 2026-08-22 の初回コミット以来7列のまま一度も変わっていない（`git log --follow` でコミット1件）
- `timepoint-map.csv` の7列のうち、汎用層（`tlf_ops.R`・`tlf_ops.sas`）が読むのは `order`・`label`・`glabel` の3列だけである。`rsparamcd` は `examples/trial-displays.sas`、`subset` は `check-identifier-length.py` が読み、`source` と `spid` は読み手が見つからない
- 2試験目で `check-identifier-length.py` を回すと ERROR 23件。`subset` 列を足すと22件になり、終了コードは1のまま変わらない。列の有無は苦情の種類を変えるだけで、宣言が空である限り落ちる
- `audit_declarations.py` を雛形のままの宣言に当てると、修正前は終了コード0で「指摘はありません」。修正後は D08 の error 6件・warning 1件で終了コード1になり、埋めるべきファイルが名指しで出る
- `primary-endpoint.csv` は雛形が鍵の行を1行持つため D08 に掛からない。値が空の行が通ることになるので、列ごとに必須を宣言する仕組みが要る（積み残しへ）
