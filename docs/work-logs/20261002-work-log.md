## 概要

GitHub 上で README のリンクがすべて外れているという報告を調べた。原因はリポジトリ側ではなく、GitHub のファイル表示ページ（`blob/...`）が一時的に 503 を返していたことだった。ファイルは何も直していない。時間を置いて開き直すと、リンクはすべて動いた。

## 決定事項

- README の相対リンクは直さない。ローカルで書いた相対リンクを GitHub 向けに調整し忘れたのでは、という仮説は外れた。相対リンクのまま GitHub で正しく描画される
- リポジトリのコラボレーター設定は変えない。settings/access の個別コラボレーター欄に `tosh13` が載っていないのは、組織のオーナーだからである。オーナーは組織の全リポジトリに admin 権限を持つので、その欄には出ない。公開リポジトリなので、コラボレーターかどうかはファイルの閲覧に関係しない

## 実測

- README のリンクは15件。リンク先13ファイルは、すべて remote のツリーに実在した。`check-md-links.py` でリポジトリ全体を調べると、45ファイル・226リンクで切れは0件だった。git 管理外のファイルを指すリンクも無かった
- 描画されたトップページの href は、`/nnh/trial-planning-and-analysis/blob/master/<path>` の正しい形だった
- headless Chrome で、ログインしない状態でリンク先を開いた。13件のうち一部は GitHub の「Unicorn!」（503）になった。失敗した件は開き直すと開くことがあった
- 描画しない `?plain=1` でも、無関係な公開リポジトリ（`octocat/Hello-World`・`cli/cli`）でも、同じく 503 になった。GitHub のステータスページは障害なしと出ていた
- curl で `blob/...` を取ると、どのリポジトリでも 503/504 になる。`tree/...`・`commits/...`・raw は 200 だった。GitHub のファイル表示ページの検証に curl は使えないので、ブラウザで開いて確かめる
