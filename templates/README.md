# 機械可読な正本の雛形

作成日：2026-08-22
改訂日：2026-09-05

新しい試験を始めるときに、`docs/` へ置く CSV と設定の雛形。列だけを持ち、中身は空である。試験固有の語彙（表題・水準の表示名・表番号）は試験ごとに書き起こすもので、他の試験から流用しない。

置き場は試験リポジトリの `docs/`。ファイル名は試験をまたいで揃える。スクリプトがファイル名で参照するため、この階層から動かさない。

## trial.json

試験固有の値をここだけが持つ。スクリプトは試験名をコードに書かず、この設定から引く。

- `trial_id` — プログラム名の接頭辞、納品パッケージ名、表題に使う識別子。`<試験ID>_ARD.sas` のように使われる
- `box_path` — データの置き場。Box のルートからの相対で、要素の配列にする。端末ごとに違う Box のルートは実行時に解決する

`scripts/boxpath.py` の `trial_id()`・`trial_dir()` と、PowerShell 側の `Get-TrialConfig`・`Get-TrialRoot` が読む。

## tlf-index.csv

図表の宣言。1行が1つの図表で、「どの表番号を、どの表示型で、どの解析の結果値から、どの並びで描くか」だけを持つ。表の作り方はここに書かない。

SAS の描画・R の描画・トレーサビリティ索引の生成の3つが同じファイルを読む。宣言の実体はこれ1つにする。

- `seq` — 報告書の並び。駆動ループはこの順に描く
- `lblid` — 表番号。`label-catalog.csv` のキー
- `display` — 表示型。`tab_` で始まれば表、`fig_` で始まれば図
- `analysis_id` — 結果値の出どころ（表示型が解析1件を描くとき）
- `output_id` — 図表グループ（表示型が複数の解析を一括で描くとき）
- `filter` — 結果値の行の絞り込み
- `groups` — 列に並べる群の識別子。区切り文字の順序が並び順の意味を持つ
- `levels` — 行に並べる水準の識別子。同上
- `item_var` — 背景表の行項目に使う列
- `item_label` — 行項目の見出しに使う固定文言のキー
- `vars` — 一覧表が表示する列の並び
- `labels` — 一覧表の列見出しのキーの並び
- `paramcd` — 図が使うパラメータ
- `where` — 図が使う被験者の絞り込み
- `group` — 図を層別する変数
- `blocks` — 複数の解析を行ブロックとして積むときの並び

表示型マクロの引数名はこの列名と同じにする。対応表を持たないことがこの設計の要点で、対応表があると表示型を足すたびに2箇所を直す作業が生まれる。

実装の詳細（データセット名、解決前のマクロ変数）をこのファイルに入れない。入れると片方の系統だけが読める列になる。

## label-catalog.csv

表示文言。表題・副題・脚注・水準の表示名を、言語ごとの対で持つ。プログラムに文言を書かない。

- `kind` — 文言の種類（表題・副題・脚注・水準・固定文言）
- `key` — 参照するキー。表番号や水準の識別子
- `label_en` — 英語の表示名
- `label_ja` — 日本語の表示名
- `order` — 並び順の番号。同じ行項目に属する水準の中での順序
- `visitnum` — 来院計画（SDTM の TV ドメイン）の `VISITNUM`。治療相の水準に与え、並び順の正本にする
- `source` — 出どころ（統計解析計画書の節番号など）
- `note` — 補足

`order` を持つのは枠組みの既定である。並びを表示名の照合順序に任せると文字符号化に依存し、セッションの符号化を変えるだけで並びが変わる。値は1つも変わらないため、系統間の突合でも前後比較でも検出できない（試験実績で12表387セルが該当した）。

`visitnum` を持つのは、治療の実施順を持っているのが `VISITNUM` だけだからである。識別子の文字順や件数の降順で並べると実際の治療順と食い違う。治療相のための専用のマスターファイルは作らず、この列で持つ。識別子を引く先が2つに分かれると同じ事実を2箇所で管理することになる。1つの治療相に与える識別子は1つだけとし、正本は ADaM の `APHASE` とする（[../pipeline/analysis-pipeline-plan.md](../pipeline/analysis-pipeline-plan.md)「図表の並び順を来院計画から決める」）。

言語を増やすときは `label_<言語コード>` の列を足す。

## level-sets.csv

水準の集合。事前に規定された水準を集合として宣言し、集計の層がそこから引く。

- `set_id` — 集合の識別子
- `level` — 水準の識別子。表示名は `label-catalog.csv` が持つ
- `impl_order` — 集計が水準を並べる順
- `display_order` — 表示の並びが集計と違うときだけ埋める
- `note` — 補足

該当0件の水準を行として残すためにこれが要る。割合を併記する表で行が消えると分母が読めず、行が消えたのか水準が存在しないのかも区別が付かない。集計の層に集合を渡せば0件の行が作られ、表示の層は行が無いものを描かずに済む。図表の宣言（`tlf-index.csv`）の `levels` は表示の並びにしか効かないので、そこへ集合を書いても行は増えない。

事前規定の時点（何年後の推定値を出すか）も集合として持つ。数値の並びを表示型の引数に持たせると、集合の宣言が無いため、解析結果メタデータでは事前規定ではなくデータ由来の水準として扱われる。水準の識別子から値そのものを機械的に導ける形（`Y<年>` など）にしておけば、値を持つのはこの CSV の行だけになる。

宣言に無い水準が結果に出たら止める。事前規定の水準だと名乗れるのはこの照合があるからで、検査を付けられない宣言は増やさない。逆に、イベントの起きた時刻のように固定データから決まる水準は集合を持てない。データ由来の水準として残るのが正しい状態なので、残る理由を書いておく。

## variable-map.csv

層ごとの変数の一覧。トレーサビリティ索引が層をまたいで辿るための対応表になる。

- `layer` — どの層の変数か（sdtm・adam など）
- `dataset` — データセット名
- `variable` — 変数名
- `label_en` — 変数ラベル。英語のみとし、日本語は `label-catalog.csv` が持つ
- `length` — 宣言長。文字型の変数だけが値を持ち、数値型は空にする
- `origin` — 由来の区分（収集・派生・規定値など）
- `predecessor` — 前の層のどの変数から来たか
- `crf_sheet` — 症例報告書の帳票
- `crf_field` — 症例報告書の入力欄
- `spec_ref` — 作成仕様のどの節が規定しているか。`<ファイル名> §<節番号>` の形
- `order` — データセットの中での変数の並び。データセットごとに1から振る通番

`spec_ref` は仕様書 HTML への直リンクになる。参照先の実在は検査で毎回確かめる。

このファイルは索引のための対応表であると同時に、変数の属性の正本でもある。ラベル・宣言長・並びを実装が持つと、その実装を持たない側で値を再現できず、系統ごとに採り方が違えばどちらが正しいかも決まらない。二重コーディングの両系統がここから引き、`itemOID` は `IT.<データセット>.<変数>` の規則で組む（[../pipeline/analysis-pipeline-plan.md](../pipeline/analysis-pipeline-plan.md)「変数の属性の正本を宣言に置く」）。

`order` を行の順ではなく列で持つのは、行順に意味を与えると、定義を読むために並べ替えただけで出力が変わるためである。標準が並びを定める層は外部標準の写しを読み、標準が定めない層だけこの列が持つ。

検査は網羅と一致の両方を見る。参照整合だけを見る検査は、成果物にあってこのファイルに無い変数を見つけない。

## timepoint-map.csv

評価時点の対応表。症例報告書の帳票名と、解析上の時点名の対応を持つ。

- `order` — 時点の並び
- `spid` — 症例報告書側の識別子
- `label` — 表示名
- `glabel` — 群化に使う識別子
- `source` — どのドメインから採るか
- `rsparamcd` — 効果判定のパラメータ
- `rsavisit` — 解析上の訪問名

この対応表を持たないと、実装が帳票名を直接読むことになり、対応がプログラムの中にしか存在しなくなる。試験実績では23時点の対応が品質管理プログラムの書式定義の中にしか無く、後から起こした。

## reference-table-rows.csv と reference-values.csv

参考併記の表（自試験の結果と、先行試験の公表値を列に並べる表）の2つ。行の定義と値を分けて持つ。

`reference-table-rows.csv` が表の構造を持つ。

- `order` — 行の並び
- `item` — 行の識別子。値の側とここで結合する
- `label` — 行ラベルの表示名のキー（`label-catalog.csv` を引く）
- `analysis_id` — 自試験の値を引く解析
- `variable_level` — その解析のどの水準を引くか
- `stat` — 引き方。`n_total`（例数）・`pct_n`（割合と分子分母）・`km_ci`（推定値と95%信頼区間）。空にすると見出しの行になり、自試験の列は空欄になる

`reference-values.csv` が公表値を持つ。試験が増えれば行が増える縦持ちにする。

- `trial` — 公表値の出どころの試験
- `item` — 行の識別子。構造の側とここで結合する
- `value` — 公表されている値。書式のまま文字列で持つ（自試験の値と桁を揃えない）
- `note` — 注記
- `source` — 出典（文献・登録番号）

分けるのは、比較する試験が増えても列を増やさずに済ませるためである。構造の側は行の定義だけを持ち、値の側は縦に伸びる。

公表値を解析結果データに置かない。解析の結果ではないものを同じ場所に置くと、二重コーディングの突合の対象に入り、突合できない行が混ざる。

表示型の側に比較対象の試験名を書かないこと。試験実績では実装が他試験の名前を直書きしており、汎用の部品として使えなくなっていた（[../examples/README.md](../examples/README.md)「表示型の判定」）。列の数と見出しは値の側にある `trial` の実値から決める。

## 使い方

1. 雛形を試験リポジトリの `docs/` へコピーする。`timepoint-map.csv` は試験で使う名前に合わせてよい
2. `trial.json` の2つの値を埋める
3. 図表案が固まったら `tlf-index.csv` と `label-catalog.csv` を書き起こし、事前規定の水準を `level-sets.csv` へ宣言する。図表案のレビュー（[../review/planning-review/checklist-tlf-shells.md](../review/planning-review/checklist-tlf-shells.md)）を通してから書くと、後から並び順や分母で戻らない
4. `variable-map.csv` は層を作りながら埋める
5. 参考併記の表を出す試験だけ、`reference-table-rows.csv` と `reference-values.csv` を埋める。出さない試験ではコピーしない

雛形に中身を残さない。表題や水準の表示名を他の試験から流用すると、その試験の語彙が紛れ込む。
