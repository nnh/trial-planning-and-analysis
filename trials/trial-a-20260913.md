# 試験A 通過記録

本枠組みで解析を1本通した最初の試験の記録である。件数と構造だけを持ち、被験者単位の情報は持たない。

数値の正本は試験側リポジトリの一次データ（決定台帳・作業ログ・検証記録・宣言の CSV）で、本書はそこから数えた値を置く。枠組み側の設計文書は実績の件数を持たず、本書を引く。ただし、原則がなぜ要るかを支える数値は根拠として各文書に残る。両者の違いは、その数が規則の説明に要るか、通した結果の報告かにある。

## 匿名化の方針

実試験名・臨床試験登録番号・実リポジトリ名を本書に書かない。枠組みリポジトリの README が定める方針に従い、匿名ラベル「試験A」で呼ぶ。症例番号・被験者単位の日付・検査値も書かない。必要なのは件数と構造であり、個別の値ではない。

## 領域と規模

血液腫瘍領域の医師主導第II相試験。登録90例、解析対象集団88例で、最大の解析対象集団と安全性解析対象集団が同数である。

受領データは CDISC 形式へ変換された16ドメインの CSV と、外部データ数件。層は受領 CSV から SDTM、ADaM、ARD、図表、納品パッケージまでで、SDTM は20ドメインの Dataset-JSON として持つ。

図表の宣言は90件（表86・図4）で、13種類の表示型で描く。宣言の正本は CSV 1つであり、二重コーディングの両系統とトレーサビリティ索引が同じものを読む。

## 使った枠組みの版

日付で指すなら、前半（2026-07-21 から 08-21）は本リポジトリの前身にあたる個人の方法論フォルダの版、後半（2026-08-22 以降）は本リポジトリの版である。工程を区間0から区間3に切る形は 2026-09-06 に置いたもので、試験Aの終盤だけがその形で回っている。前半の判断票の扱いは後述のとおり区間の定義を満たしていない。

### 立案

試験Aは立案時レビューを実施していない。以下は枠組みの検証として、解析の終わった後に同じ資料へ当てた結果である。

統計解析計画書の構造検査は error 0・warning 0・info 45。info はすべて図表案の数値プレースホルダで、実データを入れる前の枠として正常な状態を指す。0件は妥当な結果で、この文書は複数回のレビューと修正を経ており構造の欠陥が既に潰れている。

研究計画書の構造検査は error 0・warning 16。内訳は S04 が6件、S05 が3件、S09 が1件、S10 が6件。S10 の6件は連絡先の節のメールアドレスで、研究計画書としては正常である。目次と本文の見出しは207件すべて一致した。

電子症例報告書の構造定義の検査は error 15・warning 1・info 276。error の内訳は R01 が2件、R02 が4件、R03 が4件、R04 が5件。R02 の4件は参照フィールドの参照先が別シートを指しているもので、試験Aで実際に起きた欠陥と同一である。この欠陥は研究終了後の解析段階で発覚し、それまで60例全例の該当4項目が別シートの値で埋まっていた。構造定義を設計の時点で検査していれば同じ4件が同じ理由で挙がっていた。枠組みの効果を示す最も具体的な事例がこれである。

### 構築

SDTM の適合性検証は、初回（2026-08-15）が ISSUE REPORTED 31ルール・指摘19,388件。Trial Design の整備、指摘の仕分け、4ドメインの是正を経た 2026-08-20 の値が SUCCESS 213・SKIPPED 150・ISSUE REPORTED 26・EXECUTION ERROR 3・指摘17,770件で、26ルールすべてを既知として残すと決め、未仕分けは0になった。以後 2026-09-05 の2回の変更でもルールの状態・件数だけでなく明細の行まで動いていない。

SKIPPED は合格ではなく、対象のドメインや変数が無いため実行されなかったことを表す。主因は作っていないドメインと、渡していない外部辞書である。

トレーサビリティ索引の生成と検査は6,469行で ERROR 0・WARN 3。行の内訳は入力欄1,335・固定値4,494・参照179・見出し456・注記5。WARN 3件はいずれも設計どおりの状態を指すもので、欠陥ではない。

データカットは固定1回と再抽出3回の計4回。再抽出のたびに受領データの直下を差し替えて全段を回し直した。値を動かした再抽出は1回だけで、残る2回は投与記録の構造と判定欄・定量域下限の修正であり集計値を動かさない。

### 解析

決定の正本を守る検査は、仕様書が決定を述べている箇所を20箇所拾った。うち7件は決定の本文が仕様書にあったので台帳へ移した。当てるのは日付を伴う確定の言い方で、かつ同じ行が一次文書に触れているものに限る。

両系統の突合は、結果値・図表セルの台帳・受入基準の照合のいずれも食い違い0。結果値は31,075行・19列で、解析の識別子は1,478種である。図表セルの台帳は3通りで照合した。

視覚回帰は4組で一致21・食い違い0。意図した変更のたびに差分を目で確かめてから基準を取り直している。

## 新しく足した規則

枠組みそのものが試験Aから起こしたものなので、現在の規則の大半がこの1本に由来する。個々の規則は本書に写さず、それぞれの正本が持つ。

- 解析の流れ・層の定義・設計の原則 … `pipeline/analysis-pipeline-plan.md`
- 統計解析計画書の固定前に決め切る事項 … `review/sap-review/upfront-decisions.md`
- 解析の段階で見つかった欠陥の型 … `findings/analysis-findings-log.md`
- 立案時レビューで見つかった欠陥の型 … `review/planning-review/findings-log.md`
- レビューが1回で終わらない前提の設計 … `review/final-review/strategy.md`

1試験目なので、蓄積した欠陥の型はいずれも初出である。昇格の判定（2試験目で同じ型が出たら機械検査の規則にできるかを見る）は、まだ一度も行っていない。試験Aが書いた検査スクリプトは型の昇格によるものではなく、実装と同時に起こしたものである。

## 納品より後の工程

納品の後に、終了届書と審査資料に用いる総括報告書概要の作成、研究代表医師のレビュー、審査提出、追加解析の受け方、重篤な有害事象の経過記述の管理記録が発生した。枠組みはこれを受けて区間4を置いた。設計は `pipeline/analysis-pipeline-plan.md` が持つ。

試験Aで実際に決めたのは、解析用データセットを渡さず依頼で受けること、経過記述を預かっている間の保管場所とアクセス権を確認した日の状態として残すことの2つである。前者は、結果値の形式が追加解析の材料にならないこと、受領 CSV が導出変数も集団フラグも持たないこと、解析用データセットは目的に合うが日本語の使い方案内と統計ソフト向けの横持ちファイルを新たに起こすことになり規模が目的に釣り合わないこと、の3つを比べて決めた。
